# Research Evaluation Protocol & Experimental Validation (Phase 5)

## 1. Executive Objective

The objective of Phase 5 is to establish a rigorous, reproducible experimental evaluation methodology for the MDR-SIM contact-tracing simulator. This protocol defines the exact mathematical formulations, matching rules, statistical aggregation methods, and scientific boundaries used to benchmark:
1. Contact-session reconstruction accuracy
2. Wearable-to-gateway distance estimation error
3. Probabilistic exposure-risk discrimination and calibration
4. Resource efficiency and edge telemetry
5. Fair baseline comparisons and feature ablations

---

## 2. Three-Tier Evaluation Framework

To ensure scientific integrity and prevent conflation between code correctness and experimental validity, the evaluation methodology is explicitly partitioned into three tiers:

### Tier A: Pipeline Verification
Focuses on software correctness, implementation integrity, and deterministic execution:
- **Unit & Integration Tests**: Comprehensive automated test suites across all five phases (`npm run test:research`, 113+ automated tests).
- **Static Type Safety & Build Verification**: Full TypeScript type-checking and asset compilation via Vite (`npm run build`).
- **Deterministic Replay**: Bitwise reproducibility verification ensuring identical seed and configuration produce identical outputs (verified via SHA-256 matching across runs).
- **Architectural Isolation**: Static boundary assertions verifying that runtime inference engines (`src/ble/`, `src/edge/`, `src/risk/`) contain **zero** imports of hidden simulation state, ground truth, or person metadata.

### Tier B: Experimental Validation
Focuses on the scientific behavior of the algorithms under controlled simulated scenarios:
- **Multi-Seed Replication**: Replicate simulations across independent deterministic pseudorandom seeds (e.g., `[104729, 209759, 32452843, 49979687, 67867967]`) to estimate variance.
- **Statistical Aggregation**: Student's $t$-distribution 95% confidence intervals with Bessel-corrected sample standard deviations.
- **Calibration Evaluation**: Probability calibration assessment using Brier Score and Expected Calibration Error (ECE) over uniform reliability bins.
- **Robustness Analysis (Parameter Sweeps E2–E6)**: Systematic sensitivity analysis across RF noise ($\sigma_{\text{noise}}$), packet drop rate ($p_{\text{loss}}$), advertising interval ($T_{\text{adv}}$), gateway density ($N_{\text{gw}}$), and population density ($N_{\text{pop}}$).
- **Baseline Benchmarking**: Controlled comparisons against reference heuristics evaluated on identical observable inputs.
- **Feature Ablations**: Systematically disabling individual feature contributions without retraining on the test set.

### Tier C: Scientific Limitations
Explicitly documents assumptions, simplifications, and constraints inherent to the simulation paradigm:
- **Simulation-Generated Reference Labels**: Digital exposure events ($E=1$) are generated by the simulator's geometric rule ($\le 2.0\text{m}$, $\ge 30\text{s}$, same room). They are **not** clinical diagnoses or biological infections.
- **Geometric Feature–Label Dependency**: Reconstructed features (such as contact duration and proximity evidence) inherently derive from the same physical trajectories that define the reference labels. Performance reflects detection fidelity under simulator physics, not clinical efficacy.
- **Sparse Contact Events**: In realistic hospital room layouts with mobile populations, close physical encounters are naturally sparse. Individual single-hour seeds may produce zero positive exposure events, resulting in mathematically undefined discrimination metrics (AUROC/AUPRC).
- **RF Path-Loss Simplifications**: The log-distance path-loss model with log-normal shadowing abstracts complex 3D multipath, human body attenuation, room geometries, and antenna polarizations.
- **Absence of Biological Aerosol Physics**: Pathogen transport, room ventilation (air changes per hour / ACH), droplet evaporation, mask filtering, and individual susceptibility are outside the current observation model.
- **Machine-Dependent Resource Measurements**: Wall-clock execution times, latency, and CPU throughput reflect host machine capabilities and must be reported as hardware telemetry rather than universal algorithmic properties.

## 3. Critical Evaluation Boundary & Identity Resolution

### Evaluation-Only Isolation
Ground-truth coordinates, true movement trajectories, and person identities are strictly confined to `src/evaluation/`.
- Runtime modules (`src/ble/`, `src/edge/`, `src/risk/`) remain completely isolated with **ZERO** ground-truth access.
- In `src/evaluation/matching.ts`, canonical identity resolution maps ground-truth `personId` (e.g. `P-0001`) to `wearableId` (e.g. `W-0001`) solely to evaluate reconstructed wearable sessions against true physical contacts.

### Non-Clinical Disclaimer
> [!IMPORTANT]
> **SIMULATED DIGITAL EXPOSURE EVENT ONLY:**
> The reference target $E \in \{0, 1\}$ is defined strictly as a **simulated digital exposure event** conforming to the Phase 1 geometric contact definition ($\text{distance} \le 2.0\text{m}$, $\text{duration} \ge 30\text{s}$, same room).
>
> It does **NOT** represent:
> - Biological infection ($P(\text{MDR-TB infection})$)
> - Pathogen transmission
> - Infectious viral or bacterial dose
> - Clinical medical diagnosis.

## 4. Contact-Session Temporal Matching

Detected contact sessions and ground-truth physical contacts are matched using canonical pair keys and temporal Intersection-over-Union (IoU).

### Canonical Wearable Pair Mapping
Ground truth pairs $(p_A, p_B)$ are mapped via person-to-wearable lookup to $(w_A, w_B)$ and canonicalized such that:
$$w_A < w_B$$

### Temporal Intersection-over-Union (IoU)
For ground-truth interval $[t_{\text{start}}^{\text{GT}}, t_{\text{end}}^{\text{GT}}]$ and detected interval $[t_{\text{start}}^{\text{Det}}, t_{\text{end}}^{\text{Det}}]$:

$$\text{Intersection} = \max\left(0, \min(t_{\text{end}}^{\text{GT}}, t_{\text{end}}^{\text{Det}}) - \max(t_{\text{start}}^{\text{GT}}, t_{\text{start}}^{\text{Det}})\right)$$
$$\text{Union} = \max(t_{\text{end}}^{\text{GT}}, t_{\text{end}}^{\text{Det}}) - \min(t_{\text{start}}^{\text{GT}}, t_{\text{start}}^{\text{Det}})$$
$$\text{IoU} = \frac{\text{Intersection}}{\text{Union}}$$

### Matching Criteria
A detected session is matched to a ground-truth contact if:
1. They share the same canonical wearable pair.
2. $\text{IoU} \ge \text{minOverlapIoU}$ (default: $0.20$).
3. $\text{Intersection} \ge \text{minOverlapSeconds}$ (default: $5.0\text{s}$).

Candidate pairs are matched greedily in descending order of IoU to establish 1-to-1 primary matches.

### Fragmentation & Merging
- **Fragmentation**: Occurs when a single ground-truth contact overlaps with $>1$ qualifying detected session.
- **Merging**: Occurs when a single detected session overlaps with $>1$ qualifying ground-truth contact.

## 5. Contact Detection Metrics

- **True Positives ($TP$)**: Number of primary matched ground-truth contacts.
- **False Positives ($FP$)**: Detected sessions with no matching ground-truth contact.
- **False Negatives ($FN$)**: Ground-truth contacts with no matching detected session.

$$\text{Precision} = \frac{TP}{TP + FP} \quad (\text{if } TP + FP = 0 \implies 0)$$
$$\text{Recall} = \frac{TP}{TP + FN} \quad (\text{if } TP + FN = 0 \implies 0)$$
$$F_1 = 2 \cdot \frac{\text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}} \quad (\text{if } P + R = 0 \implies 0)$$

### Temporal Duration & Boundary Errors
For all matched pairs $i = 1, \dots, TP$:
- Duration Error: $e_i = \hat{T}_i - T_i$
$$\text{MAE} = \frac{1}{TP} \sum_{i=1}^{TP} |e_i|, \quad \text{RMSE} = \sqrt{\frac{1}{TP} \sum_{i=1}^{TP} e_i^2}$$
- Median Absolute Error and 95th Percentile ($P_{95}$) Absolute Error are computed from sorted $|e_i|$.
- Start-time error ($\hat{t}_{\text{start}} - t_{\text{start}}$) and end-time error ($\hat{t}_{\text{end}} - t_{\text{end}}$) are reported similarly.

## 6. Wearable-to-Gateway Distance Metrics

Evaluates the accuracy of log-distance path-loss inversion $\hat{d}$ from filtered RSSI observations against true Euclidean coordinates $(x_p, y_p)$ to gateway $(x_g, y_g)$:

$$d_i = \sqrt{(x_{p,i} - x_{g,i})^2 + (y_{p,i} - y_{g,i})^2}$$
$$\text{MAE}_{\text{dist}} = \frac{1}{N} \sum_{i=1}^N |\hat{d}_i - d_i|, \quad \text{RMSE}_{\text{dist}} = \sqrt{\frac{1}{N} \sum_{i=1}^N (\hat{d}_i - d_i)^2}$$

> [!WARNING]
> This measures **wearable-to-gateway** RF estimation error under log-normal shadowing and multipath. It is **NOT** person-to-person ranging.

## 7. Risk Discrimination & Calibration Metrics

### AUROC (Area Under the Receiver Operating Characteristic Curve)
AUROC evaluates the probability that a randomly chosen positive exposure event is ranked higher than a randomly chosen negative event. Computed via the exact Wilcoxon rank-sum / Mann-Whitney $U$ statistic with average ranks assigned to tied predictions:

$$U = R_{\text{pos}} - \frac{N_{\text{pos}}(N_{\text{pos}} + 1)}{2}$$
$$\text{AUROC} = \frac{U}{N_{\text{pos}} \cdot N_{\text{neg}}}$$

If all labels are positive ($N_{\text{neg}} = 0$) or all negative ($N_{\text{pos}} = 0$), AUROC is mathematically undefined and reported as `undefined`.

### AUPRC / Average Precision (Step-Wise Precision-Recall Integration)
Linear trapezoidal interpolation on precision-recall curves is known in machine learning literature to systematically overestimate the area under the PR curve because precision varies non-linearly with recall between operating points (Davis & Goadrich, 2006).

Therefore, AUPRC is evaluated using **step-wise Average Precision (AP)** across unique descending score thresholds:

$$\text{AP} = \sum_{k=1}^M (R_k - R_{k-1}) \cdot P_k$$

where:
- $t_1 > t_2 > \dots > t_M$ are the unique predicted probability thresholds.
- $P_k = \frac{TP_k}{TP_k + FP_k}$ is the precision achieved at threshold $t_k$.
- $R_k = \frac{TP_k}{N_{\text{pos}}}$ is the recall achieved at threshold $t_k$, with $R_0 = 0$.
- Samples with tied scores are evaluated together at threshold $t_k$, eliminating arbitrary tie-breaking instability.
- If $N_{\text{pos}} = 0$ or $N_{\text{neg}} = 0$, AUPRC is reported as `undefined`.

### Calibration & Reliability Analysis
- **Brier Score**:
  $$\text{Brier} = \frac{1}{N} \sum_{i=1}^N (p_i - y_i)^2$$
- **Expected Calibration Error (ECE)**:
  Partition $[0, 1]$ into $M = 10$ uniform bins $b_1, \dots, b_M$.
  $$\text{ECE} = \sum_{m=1}^M \frac{|B_m|}{N} \left| \text{acc}(B_m) - \text{conf}(B_m) \right|$$
  where $\text{acc}(B_m) = \frac{1}{|B_m|} \sum_{i \in B_m} y_i$ and $\text{conf}(B_m) = \frac{1}{|B_m|} \sum_{i \in B_m} p_i$.

## 8. Statistical Aggregation Across Seeds

Independent random simulation seeds serve as true experimental replicates ($N$).
For any metric $M$ across seeds:
- Mean: $\bar{x} = \frac{1}{N} \sum_{i=1}^N x_i$
- Sample Standard Deviation (Bessel's correction): $s = \sqrt{\frac{1}{N-1} \sum_{i=1}^N (x_i - \bar{x})^2}$
- 95% Confidence Interval using Student's $t$-distribution with $df = N - 1$:
  $$\bar{x} \pm t_{0.975, N-1} \cdot \frac{s}{\sqrt{N}}$$
- For $N < 2$, the confidence interval is strictly reported as **unavailable** (`undefined`).

## 9. Baseline Models

All four evaluation methods receive **identical observable `ExposureRecord[]` inputs** derived from edge reconstruction:

> [!NOTE]
> **Provenance Disclaimer:** These baseline algorithms are deliberately constructed experimental reference baselines designed to benchmark specific feature subsets. They do not represent established clinical standards or proprietary commercial systems.

1. **Proximity-Only Baseline**:
   $$P(E=1) = \max(0.01, \min(0.99, \text{proximityEvidence}))$$
   Tests whether spatial co-presence alone is sufficient to prioritize exposure without duration or recurrence.

2. **Proximity + Duration Baseline**:
   $$\text{score} = 0.5 \cdot \text{proximityEvidence} + 0.5 \cdot \min(1.0, \text{durationSeconds} / 300)$$
   $$P(E=1) = \max(0.01, \min(0.99, \text{score}))$$
   Tests an additive heuristic combining normalized proximity and linear duration.

3. **Legacy Heuristic Baseline**:
   Weighted additive model preserved from pre-Phase 4 implementations ($0.35 \cdot \text{dur} + 0.35 \cdot \text{RSSI} + 0.15 \cdot \text{rep} + 0.15 \cdot \text{source}$).

4. **Proposed Bayesian Model**:
   Causal Bayesian log-odds likelihood ratio model with Dirichlet smoothing:
   $$\ln \mathcal{O}(E=1 \mid X) = \ln \mathcal{O}(E=1) + \sum_{j \in \text{features}} \ln \text{LR}_j$$
   $$P(E=1 \mid X) = \frac{\mathcal{O}(E=1 \mid X)}{1 + \mathcal{O}(E=1 \mid X)}$$

## 10. Feature Ablation Protocol

To quantify individual feature utility without introducing test-set leakage:
- Ablations are constructed by filtering `selectedFeatures` on the frozen `FittedRiskModel`.
- The ablated model is **never retrained or tuned** on test-set observations.
- All ablated variants are evaluated on identical test records and identical random seeds:
  1. `Full Model`: All 5 features (`duration`, `proximity`, `encounterCount`, `cumulativeDuration`, `sourceStatus`).
  2. `Minus Duration`: Excludes `duration`.
  3. `Minus Proximity`: Excludes `proximity`.
  4. `Minus Recurrence`: Excludes `encounterCount` and `cumulativeDuration`.
  5. `Minus Source Status`: Excludes `sourceStatus`.

## 11. Parameter Sweeps (E2–E6) & Scenario Boundaries

Robustness sweeps vary operational parameters to test pipeline resilience:
- **E2: RSSI Noise Sweep** ($\sigma_{\text{noise}} \in [0, 2, 4, 6, 8, 10]\text{ dB}$): Tests resilience to multipath variance.
- **E3: Packet Loss Sweep** ($p_{\text{loss}} \in [0.0, 0.05, 0.10, 0.25, 0.50]$): Tests resilience to RF packet dropping.
- **E4: Advertising Interval Sweep** ($T_{\text{adv}} \in [200, 500, 1000, 2000]\text{ ms}$): Tests sensitivity to beacon emission rate.
- **E5: Gateway Density Sweep** ($N_{\text{gw}} \in [4, 8, 12, 16]$): Tests spatial coverage effects.
- **E6: Population Density Sweep** ($N_{\text{pop}} \in [20, 50, 100, 150]$): Tests multi-agent crowding and encounter frequency.

### Ground-Truth Invariance vs Legitimate Scenario Modification
- **Observation-Only Parameters**: Parameters E2, E3, and E4 alter *only* the BLE observation generation (`src/ble/`). They must leave the Phase 1 movement states and ground-truth contacts **100% byte-for-byte identical**.
- **Physical Scenario Parameters**: Parameters E5 (gateways) and E6 (population size) define the physical environment and agent count. Changing them legitimately modifies the simulated physical world and ground truth.

## 12. Privacy & Security Evaluation Protocol (Phase 6)

### Objective
Quantify the privacy, unlinkability, and utility trade-offs of rotating pseudonymous identifiers in hospital BLE contact-tracing networks under formalized adversarial models.

### Threat Model & Attack Benchmark Protocols
Evaluates three standardized attacker profiles defined in `docs/PRIVACY_THREAT_MODEL.md`:
1. **Attacker A (Passive Local Observer)**: Eavesdrops at single gateway; measures pseudonym tracking window duration.
2. **Attacker B (Multi-Observation Linkage Attacker)**: Reconstructs trajectory continuity across pseudonym boundaries using observable temporal, spatial, and RSSI similarity.
3. **Attacker C (Baseline Unauthorized Resolver)**: Infers person identity using observable dwell time vectors under a conservative side-information model (gateway layout and population size).

### Empirical Privacy Metrics
- **Same-Device Linkage Precision, Recall, and F1**:
  $$\text{Precision} = \frac{TP_{\text{link}}}{TP_{\text{link}} + FP_{\text{link}}}, \quad \text{Recall} = \frac{TP_{\text{link}}}{TP_{\text{link}} + FN_{\text{link}}}$$
- **Empirical Unlinkability Proxy**:
  $$\text{UnlinkabilityProxy} = 1 - \frac{TP_{\text{link}}}{\text{TotalSameDeviceTransitions}}$$
  *(Reported strictly as an empirical proxy under the assumed attacker model, NOT formal mathematical unlinkability).*
  - **Zero-Transition Condition (P1 / Static Identifiers)**: When identifiers do not rotate, $\text{TotalSameDeviceTransitions} = 0$. In this condition, linkage success rate and the unlinkability proxy are **strictly undefined (reported as `null` / `N/A`)**. It must **never** be reported as $1.0000$. Instead, the system explicitly reports `totalTransitions = 0` and records the **identifier persistence duration** ($\bar{D}_{\text{persist}} = 3600\text{s}$).
- **Identity Inference Accuracy & Chance Baseline**:
  - Reports empirical Top-1 and Top-$k$ rank accuracy against candidate population.
  - Performance is evaluated relative to the **theoretical uniform-random chance baseline**:
    $$\text{ChanceBaseline} = \frac{1}{N_{\text{pop}}}$$
    *(e.g., $1/50 = 0.0200$ for $N=50$). Reports $\Delta = \text{Top1} - \frac{1}{N_{\text{pop}}}$ across random seeds.*
- **Pseudonym Collision Analysis**:
  Empirical collision rate compared against the theoretical birthday bound:
  $$P(\text{collision}) \approx 1 - \exp\left(-\frac{k(k - 1)}{2S}\right)$$

### Privacy–Utility Trade-Off Protocol
Evaluates edge reconstruction under two distinct views:
1. **Authorized View**: Contact detection where edge processing resolves rotating pseudonyms through the simulated authorization boundary (`IdentityRegistry`), preserving session continuity.
2. **Unprivileged View**: Contact detection where the observer cannot resolve rotation, resulting in session fragmentation across pseudonym transitions.
3. **Utility Impact**: Measures session count inflation, contact duration attenuation, and missed contact rates.

### Required Experiment Suite (P1–P7)
- **P1: Baseline without Rotation**: Static identifiers ($T_{\text{rot}} = \infty$, $\bar{D}_{\text{persist}} = 3600\text{s}$); totalTransitions = 0, unlinkabilityProxy = N/A; establishes baseline tracking window.
- **P2: Rotation Interval Sweep**: Varies $T_{\text{rot}} \in [30\text{s}, 60\text{s}, 120\text{s}, 300\text{s}, 600\text{s}]$.
- **P3: Rotation + RSSI Noise Sweep**: Varies RF noise $\sigma_{\text{noise}} \in [0, 6, 10]\text{ dB}$ at constant 60s rotation to quantify degradation of Attacker B trajectory linkage under noisy observations.
- **P4: Rotation + Packet Loss**: Varies packet loss $p_{\text{loss}} \in [0.0, 0.05, 0.20, 0.50]$.
- **P5: Rotation + Gateway Density**: Varies gateway count $N_{\text{gw}} \in [4, 8, 12]$.
- **P6: Privacy–Utility Trade-Off**: Quantifies session fragmentation and duration error across rotation intervals.
- **P7: Multi-Seed Replication**: Evaluates privacy metrics across independent random seeds with Student's $t$ 95% confidence intervals.
